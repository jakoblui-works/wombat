## [Unreleased]

### Added

- With Claude Code, `/context` shows Claude's own colour for each category, and `/memory` and `/agents` beside the memory files and custom agents.
- The agent service reports an agent's context breakdown on request (`POST /agents/:id/context`): the model, tokens used out of the window, the usage by category, and lists of memory files, custom agents, skills and MCP tools (paths in your home shown with `~`). It runs `/context` as a hidden turn that leaves nothing in the chat, the log or the agent list; while a turn runs it answers `busy`, and for a tool that can't report one, `unsupported`. `GET /harnesses` lists each tool's `features` (`context` for Claude Code).
- The agent service tracks each agent's prompt cache: `GET /agents` shows how long it lives (5 min or 1 h) and when it was last used, so the app can show the time left. It is kept in memory only, never stored.
- A status bar along the bottom of the app shows the agent service ("Service · running 6 h 15 min · 1 agent"), amber with a warning when it runs older code than the app ("older than the app") or doesn't match this app's version, "connecting…" while it connects, and "not connected" in red when it can't be reached. Screen readers announce each change. Clicking it opens a panel with when it started, why it isn't connected, the agents with a process (while connected), and Stop service and Restart. When the app finds a service already running as it starts, a notice says since when (or, for a service too old to say, only that it was running) and, if it is older than the app, offers Restart. A service the app started itself brings no notice, and a dismissed notice stays away, also after a reload of the window, until Wombat starts again. File has a new Restart Service item. The dot at the bottom of the activity bar is gone; the status bar replaces it.
- The footer's settings are a button naming the model and effort ("Opus 5.5 · High") that opens a settings dialog, and the mode has its own button. The dialog lists every setting under its name as a heading, with its description below: choices as a list with a check on the current one, effort as a stepped slider, on/off settings as switches. A pick applies at once and the dialog stays open. A tool can bring its own footer parts, and can hide settings from the dialog (Claude Code's `agent` setting is hidden).
- A stopped agent's message box is read-only (the text stays selectable), Send is off, and a line under it says "This agent isn't running. Start a new agent to continue." The footer's Settings and Mode buttons are off too and an open settings dialog closes; `/context` isn't offered either.
- The context ring warns before the limit (amber from 80 %, red from 95 %) and shows the prompt cache: its tooltip adds "Cache 1h · 42 min left" (counted down every 30 s), and the ring dims once the cache has expired. The tooltip no longer shows a cost.
- Typing `/context` opens a "Context usage" dialog for tools that offer it (Claude Code): the model, tokens used out of the window, a bar and table of the categories, and the lists of memory files, agents, skills and MCP tools. It leaves nothing in the chat, and while the agent works it says "Available once the agent is idle".
- A footer under the message box: the agent's tool (picked in New agent, fixed for the chat), its settings (selects, switches; shown as the agent reports them, changeable at any time, a refused change says why under the footer) and a context ring, with a clearly visible track and the share as text ("3%"), whose tooltip (after 200 ms) gives the tokens used out of the window.
- A working agent says what it is doing: its chat shows a line above the message box ("Thinking…", "Writing…" or "Running <tool>") and its row in the Agents list a second line ("Working · Running Bash").
- The Agents sidebar lists the agents grouped by state (Waiting on me, Working, Done, Error; stopped agents under Done) with title, folder, branch, an excerpt of the agent's own latest message as its chat shows it (a sub-agent's text doesn't show there) and the time since you last interacted. A row opens or focuses the agent's chat tab; its menu stops the agent while its process runs (done agents too, and agents whose turn failed) or deletes it (delete asks first). New agent picks the folder (the workspace root first, then its repos; the last one used by default) and takes the first message. The service lists those folders at `GET /repos`.
- An agent's chat: messages as Markdown with highlighted code, tool calls as one line each that expand to their input, output and text (long texts clipped, saying how much was left out), reasoning collapsed, and the agent's plan pinned on top. Permission requests are answered where they appear (Approve, Reject and any other option); answered ones show the outcome. The message box sends on Enter (Shift+Enter for a new line), keeps your text when a send fails, and has Cancel while the agent works. The header has Stop (while the process runs) and Delete. Agent content stays text: raw HTML shows as written, only https links are links (opened in your browser), and images never load.
- Edit approvals: an agent's request to edit a file shows in the chat as a card with the file, its +/− line counts, the changed lines with three lines of context, and Approve and Reject; a change too large to show there is reviewed side by side. "Open side by side" opens the edit in a diff tab beside the chat (Monaco's diff editor, read-only) with the same buttons; answering in either place shows the outcome in both. An answered request's diff tab stays until you close it and doesn't reopen on the next start. A permission request and the tool call it asks about show as one item; once answered, it expands to the tool call's output. A tool call's diff (an edit that wasn't asked about) shows as the same compact diff.
- Needs me: the right sidebar lists every waiting agent's open permission requests (or "Waiting for you" when it has none), newest first, with the agent, what it asks and the time since. A click, like a click on a notification, switches to Agents and opens the agent's chat scrolled to the request (the oldest one for a notification). The title bar's Needs me toggle shows how many wait.
- An integrated title bar: the File, Edit, View and Window menus on the left (each item shows its key), the workspace name in the middle (drag the window by it), the Needs me toggle and the window's own controls on the right. The Edit items act on the field you were typing in.
- Splits that open an empty group: a split button on each group's tab bar (click splits right, Alt+click splits down) and a tab's context menu (Split Up, Down, Left, Right, and Close) act on the tab or group you used them on, and the new group is the active one, ready for the next thing you open. The commands are `view.split.right|down|left|up`. Empty groups are saved with the layout, and Ctrl+W closes the active one when it has no tab (never the last group).
- The app scaffold: a pnpm workspace with shared types, the agent service and the desktop app.
- The agent service's API, on 127.0.0.1 only: start a Claude Code agent in a repo of the workspace, send it messages, answer its permission requests, cancel a turn, and stop or delete the agent, with a stream of alerts whenever something changes. Every request needs the token from the discovery file.
- Agents use your own `claude` login. They get only an allowlisted environment: never the service's token, its `WOMBAT_*` settings or `ANTHROPIC_API_KEY`; `CLAUDE_CONFIG_DIR` is passed on when it's set.
- Agent history is kept in `$XDG_STATE_HOME/wombat/service.db` (`~/.local/state/wombat/service.db` by default, only you can read it), so it survives a restart of the service.
- Each agent runs in its own systemd user scope in `wombat-agents.slice`, so stopping or deleting it ends everything it started. The service stops anything left in that slice when it starts and when it shuts down. Without a usable systemd user manager, agents run as plain process groups and the service logs a warning.
- The agent service runs as a process: configured by `WOMBAT_WORKSPACE` (required), `WOMBAT_PORT` (default 14900, 0 for any free port) and `WOMBAT_STORE`; it writes `$XDG_RUNTIME_DIR/wombat/service.json` (only you can read it) so the app can find it, lets only one instance run per runtime folder (a second start names the running one and exits 0; the lock of a service that died is taken over), logs to stderr only, and on SIGINT or SIGTERM stops its agents and removes the file.
- Items: set `WOMBAT_ITEMS` to a folder of structures and item files and the service lists the structures (`GET /structures`), a structure's items (`GET /structures/:id/items`) and one item by handle or old handle (`GET /items/:handle`), invalid items included with their problems. Without `WOMBAT_ITEMS` these routes answer `items_not_configured`. The routes only read; agents change items through the agent tools, and you decide their proposals over the proposal routes.
- Agent tools: with `WOMBAT_ITEMS` set, every agent gets Wombat's ten item tools over MCP at `/mcp` to describe the structures, search, read, create, update and delete items, or propose those changes. A structure's access level (`hidden`, `read`, `propose` or `edit`) decides what an agent sees and may do, and locked fields can't be changed by an agent. Claude Code pre-allows the wombat tools, so it doesn't ask before each call.
- Agent token: each agent gets its own token for `/mcp`. It opens only `/mcp` (never the app's routes), is kept only in memory, and is revoked when the agent stops, is deleted or the service exits.
- Proposals: a proposal from an agent is stored in the service's store, listed with `GET /proposals?status=` and decided with `POST /proposals/:id/approve` or `POST /proposals/:id/reject`; each change sends a `proposal` alert. Approving re-checks the item's version and the structure's settings, and answers `conflict` with the reason instead of overwriting a change made since. A proposed create in a free-named structure carries its file path in its own `file` field (null for every other proposal), apart from its `fields` (title, body and properties), so a property named `file` is proposed like any other.
- Instructions file: the items of every structure marked `instructions: full` (each item in full) or `instructions: index` (each item's title and first line) are rendered into `<workspace>/.wombat/AGENTS.md`, outside every repo, read-only, with handles and never anything hidden. The service keeps it current: at start, after each of its writes and approvals, and shortly after you edit an item or a `_structure.yaml` by hand. Every new Claude Code agent gets it appended to its system prompt; agents already running keep the one they started with. A structure marked for instructions can't have `access: edit`, so every change to the instructions goes through your approval, and a file over 64 KiB is sent as an index of every structure.
- Agent summaries show what the app's agent list needs: the agent folder's git branch, an excerpt of the agent's own latest message as its chat shows it (a sub-agent's text doesn't show there), when you last sent it a message or answered it, and its open permission requests. A store from an earlier version is upgraded in place when the service starts.
- The service stores the agent's plan and its reasoning as they arrive, instead of skipping them.
- Agent summaries say what a working agent is doing right now (thinking, writing, or running a tool, with the tool's title), read from its log the same way its chat reads it, so the agent list and the chat agree.
- The agent's settings (its model, mode and other options the agent offers) are kept in its history from the start and whenever they change, and `POST /agents/:id/config` changes one. A value the agent doesn't offer is refused before it reaches the agent, and when the agent itself says no, the answer (`agent_error`) carries its reason.
- Every turn in an agent's history ends with a `turn_ended` entry: `error` when the turn failed, `stopped` when the agent's process ended during it.
- Agent summaries say whether the agent's process still runs (`hasProcess`).
- `POST /shutdown` stops every agent (their history is kept) and ends the service.
- An alert stream client that stops reading is disconnected once too many alerts wait for it. The stream doesn't replay: after any reconnect the app reads the agents, the proposals and each open agent's log again.
- A desktop app skeleton with secure defaults: context isolation on, no Node in the renderer, a strict content security policy.
- The desktop app asks for the workspace folder on first start, remembers it in `~/.config/Wombat/settings.json` (only you can read it), and starts the agent service for it when none is running. A service running for another workspace is restarted only when you say so.
- The desktop app reaches the service only through its main process, which holds the token and allows only the service's app routes. Its main process tracks whether it's connecting, connected, reconnecting, incompatible with the service's version, or failed, and reconnects when the service restarts or moves port.
- Quitting while any agent's process runs (done agents too) asks whether to stop them or leave them running ("Don't ask again" turns the question off). The File menu has Switch Workspace and Stop Service and Agents; both ask before stopping agents. Restarting a service from an older version of Wombat asks, then replaces it.
- A desktop notification says when an agent is waiting for you, without anything from the agent in it.
- The app's page is served with a content security policy header and a fresh nonce on every load; UI libraries (Tailwind, Base UI, dockview, Shiki, Monaco's diff editor) run under it.
- The desktop app has a workbench: an activity bar with five activities (Agents, and four that name the step that fills them), a sidebar, a split, tabbed editor area and a collapsible right sidebar. Agents opens each agent's chat in a tab. The layout (splits, tabs, sidebar widths) reopens per workspace; tabs of deleted agents close, and a layout that can't be restored opens the default without overwriting the saved one.
- The desktop app shows the connection to the service at the foot of the activity bar. When it's lost (or can't be made), a banner says so with a Restart button, and the views stay as they were, dimmed and unusable, until it's back.
- Zoom: Ctrl+= (also Ctrl+Shift+= and Ctrl+Numpad+) zooms in, Ctrl+- (and Ctrl+Numpad-) zooms out and Ctrl+Numpad0 resets, in steps like VS Code's, between about 40% and 250%. A note shows the new level for a moment; the level is the same in every window and is kept in `settings.json` for the next start.
- Keyboard shortcuts: Ctrl+W closes the active tab, Ctrl+Alt+B shows or hides the right sidebar, Ctrl+Shift+W closes the window and Ctrl+Q quits (asking about running agents as before). Typing in a text field or the editor keeps plain keys for the text.
- CI that lints, type-checks, tests, builds and runs the desktop end-to-end tests on every push and pull request.
- Code in the chat is highlighted in TypeScript, TSX, JavaScript, JSON, shell (`bash`, `sh`), Python, YAML, Markdown, diff, Nix, CSS, HTML and SQL; the diff tab highlights JSON, Python, shell, YAML, Markdown and CSS files besides TypeScript and JavaScript.
- A service from before this app (one that doesn't say which workspace it runs for) shows as incompatible, saying it predates the app; Restart stops it and its agents and starts the app's own service (a service too old to stop that way makes Restart fail, saying how to stop it).
- The Wombat logo: a mark and a symbol, in colour and in one colour, in `app/desktop/assets/brand/`; the mark heads the README.
- The agent service reports when it started and which code it runs: `GET /version` answers `startedAt` and `codeId` (a hash of its source).
- The app knows when the running service is older than the code on disk: it checks on each connect and every minute while connected, so a service that goes stale while the app runs shows it too.

### Changed

- The app needs Node 26 or newer (was 24).
- Quitting with no agent process stops the agent service with the app, without asking. With agents that have a process, the question names how many and offers Keep running, Stop agents and quit, or Cancel; "Don't ask again" remembers the answer (an earlier "Don't ask again" stays Keep). A service kept running at quit is announced by a desktop notification ("The agent service is still running with N agents. Open Wombat to stop it.").
- Restart Service works in every connection state: it asks first only when agents have a process, then stops the service and starts it from the code on disk. A Restart that fails says why in a dialog, whatever the app shows.
- A service of the app's whose process runs but doesn't answer is never joined by a second one: opening Wombat, Restart and Switch Workspace fail instead, naming its pid and how to stop it.
